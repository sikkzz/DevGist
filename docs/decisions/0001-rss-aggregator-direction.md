# ADR-0001: 크롤러가 아닌 RSS 수집기 + 본문 전문 추출 리더로 진행

> **상태**: Accepted
> **날짜**: 2026-06-03
> **결정자**: @sikkzz (with Claude)
> **관련 문서**: [PROJECT_ROOT](../PROJECT_ROOT.md)

---

## 맥락 (Context)

처음 아이디어는 빅테크 기술 블로그 글을 **크롤링**해 모아보는 서비스였다. 출퇴근길에 휴대폰으로 개발자 인사이트를 전문 그대로 읽고 싶다는 욕구가 1순위다. 크롤링 방식은 약관/저작권 리스크와 유지보수 부담(셀렉터 깨짐)이 크다. 정식 경로로 같은 목적을 달성할 방법이 필요했다.

## 결정 (Decision)

**선택**: 무단 크롤링 대신 **RSS/Atom 피드 수집 + 본문 전문 추출 리더**로 진행한다.

- 피드의 `content:encoded`로 전문을 받을 수 있으면 그대로 사용한다.
- 전문이 부실한 피드는 원문에서 `@mozilla/readability`로 **본문만 추출**한다. (요약이 아니라 추출)
- 코드/이미지가 손실되는 등 추출 품질이 낮으면 **원문 링크로 fallback**(depth-2)한다.
- **본문을 임의로 요약/압축하지 않는다.** (프로젝트 핵심 제약)

## 이유 / 트레이드오프

- **얻는 것**: 정식 경로(RSS) → 약관/저작권 리스크 ↓, 피드 구조가 안정적이라 유지보수 ↓. 전문 리더 모드로 depth-1 읽기 경험 확보.
- **포기하는 것**: RSS를 제공하지 않는 블로그는 수집 불가. 일부 피드는 전문이 아닌 요약만 제공 → 추출/fallback 단계 필요.
- **법적 정당성**: 개인 사적 이용 범위에서 전문 저장이 정당화된다. 공개 시에는 인증 게이트 또는 `noindex`로 검색 노출을 막아 정당성을 유지한다.

## 검토한 대안

| 대안                    | 장점                         | 단점                                       | 제외 이유                               |
| ----------------------- | ---------------------------- | ------------------------------------------ | --------------------------------------- |
| A. HTML 크롤링          | RSS 없는 블로그도 수집       | 약관/저작권 리스크, 셀렉터 깨짐 유지보수   | 리스크·유지보수 부담이 본진 목적에 과함 |
| B. RSS 수집 + 전문 추출 | 정식 경로, 안정적, 전문 보존 | RSS 없는 블로그 제외, 일부 추출 필요       | **채택**                                |
| C. 요약만 보여주기      | 저장 부담 ↓                  | 본문 전문 보존 제약 위반 (1순위 가치 훼손) | 핵심 제약과 정면 충돌                   |

## 결과 / 영향

- 수집 파이프라인은 RSS 파서 → `content:encoded` 확인 → 부족 시 readability 추출 → 실패 시 원문 fallback 순서로 설계한다.
- `Article.contentExtracted` 플래그로 추출 경로를 추적한다.
- 본문 요약/압축 로직은 **도입하지 않는다.**

## 재검토 트리거

- 자주 보는 블로그가 RSS를 제공하지 않아 수집 공백이 클 때 → 개별 어댑터(정식 API 등) 검토.
- 공개 배포를 결정할 때 → 인증/`noindex` 게이트 설계.
