# ADR-0008: 글 주제 분류 — 무료 키워드+피드태그 규칙 (메타데이터)

> **상태**: Accepted
> **날짜**: 2026-06-04
> **결정자**: @sikkzz (with Claude)
> **관련 문서**: [ADR-0001](./0001-rss-aggregator-direction.md), [리더 UI Spec](../specs/feature-reader-ui.md)

---

## 맥락 (Context)

리더 목록을 **주제별**(프론트엔드/백엔드/AI 등)로 거르고 싶다. 주제는 **글 단위**다 — 한 회사 블로그가 여러 주제를 다루므로 피드(회사) 단위 분류로는 안 된다. 따라서 글마다 주제 태그가 필요하다.

검증 결과: 피드의 `<category>` 태그는 절반(20/39)이 **0% 제공**, 주는 곳도 어휘가 제각각(355종, 노이즈 다수)이라 단독으로는 부족하다. 유료 LLM 분류는 품질이 좋지만 사용자가 **무료**를 원한다.

## 결정 (Decision)

**무료 규칙 기반 멀티라벨 분류**를 채택한다.

- 입력: 글 **제목 + 요약 + 피드 `<category>` 태그**를 합친 텍스트.
- 주제별 **키워드 사전**(한/영)에 매칭 → 해당하는 주제를 모두 부여(멀티라벨). 매칭 없으면 `etc`.
- 분류 시점: **수집(ingest) 시** 계산해 `Article.topics String[]`에 저장. 사전 변경 시 재분류용 admin 엔드포인트 제공.
- 영어 단어는 단어 경계(`\b`) 매칭(`ai`가 `main`에 안 걸리게), 한글은 부분 문자열 매칭.

**주제셋(고정)**: `frontend · backend · infra · mobile · ai · data · qa · security` (+ `etc`).

## 이유 / 트레이드오프

- **얻는 것**: 무료·의존성 0·결정적. 피드 태그를 신호로 써서 절반은 정확도↑, 나머지는 제목·요약로 커버. 사전을 보강하면 점진 개선.
- **포기하는 것**: LLM 대비 정확도·뉘앙스 한계(오분류·미분류 존재). 키워드 사전 유지보수 필요.

## 제약과의 관계 (중요)

[ADR-0001]의 1순위 제약은 "**본문** 요약/AI 가공 금지"다. 본 분류는 **본문을 건드리지 않고 메타데이터(topics)만 부여**하므로 제약 위반이 아니다. 본문은 여전히 무손실 보존된다. (향후 LLM 도입을 검토하더라도 '분류 메타데이터' 용도에 한정하고 본문은 불변 유지.)

## 검토한 대안

| 대안                       | 품질           | 비용/의존성       | 제외 이유                                                 |
| -------------------------- | -------------- | ----------------- | --------------------------------------------------------- |
| A. LLM(Haiku) 멀티라벨     | 높음           | API키 + 소액 비용 | 사용자가 무료 선호 → 보류(추후 재검토 가능)               |
| B. 키워드+피드태그 규칙    | 중             | 무료·0            | **채택**                                                  |
| C. 피드 `<category>`만     | 낮음(들쭉날쭉) | 무료              | 절반이 미제공·어휘 난립 → 단독 불가(규칙의 신호로만 활용) |
| 회사 단위(빅테크/스타트업) | —              | —                 | 주제 탐색 욕구와 불일치 → 폐기                            |

## 결과 / 영향

- 스키마: `Article.topics String[] @default([])` (+ 마이그레이션).
- `src/lib/feeds/classify.ts`(키워드 사전·분류), parse가 `<category>` 수집 → ingest가 분류·저장.
- 리더: 회사 카테고리 탭 → **주제 탭**(`?topic=`, `topics has` 필터). `Feed.category`는 데이터로 잔존(미사용).
- 기존 글 백필 + 사전 개선 후 재분류용 `/api/admin/reclassify`(토큰 보호).

## 재검토 트리거

- 오분류가 거슬릴 만큼 많아지면 → 사전 보강, 또는 LLM(A) 메타데이터 분류로 승급.
